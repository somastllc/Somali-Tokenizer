# somali-tokenizer

Somali ByteLevel BPE tokenizer for Rust. Loads, validates, and runs the `somali-bpe`
artifacts: a 48,000-token ByteLevel BPE trained on the
[Somali NLP Corpus](https://github.com/somastllc/somali-nlp-corpus).

Built on the Hugging Face [`tokenizers`](https://crates.io/crates/tokenizers) crate, so
artifacts stay in the standard `tokenizer.json` format and the same file loads in
`transformers` from [`somast/somali-tokenizer`](https://huggingface.co/somast/somali-tokenizer).

## Benchmark

On FLORES-200 Somali, this tokenizer needs **1.374 tokens per word**. For the same text,
GPT-4o's tokenizer needs 1.975 (1.44× as many tokens), GPT-4's 2.552 (1.86×), and Llama 3's
2.527 (1.84×), all with vocabularies 2 to 5 times larger. Full results:
[BENCHMARKING.md](https://github.com/somastllc/Somali-Tokenizer/blob/main/docs/BENCHMARKING.md).

## Library

```rust
use somali_tokenizer::SomaliTokenizer;

let tokenizer = SomaliTokenizer::v2()?; // bundled release, no network
let encoding = tokenizer.encode("Soomaaliya waa dal ku yaal Geeska Afrika.")?;
println!("{:?}", encoding.tokens);
let text = tokenizer.decode(&encoding.ids, false)?;
```

Other constructors:

- `SomaliTokenizer::from_file(path)` loads any `tokenizer.json`.
- `SomaliTokenizer::from_pretrained("somast/somali-tokenizer", None)` downloads from the
  Hugging Face Hub (feature `http`; reads `HF_TOKEN` for private repositories).

Every constructor validates the artifact against the v2 contract: model type, no unknown
token, NFC normalizer, ByteLevel pre-tokenizer with `add_prefix_space = false`, ByteLevel
decoder and post-processor, the 16 special tokens at ids 0 to 15, and all 256 byte symbols.
An artifact that fails is rejected with `Error::Contract` naming the field.

## Command line

```bash
cargo install somali-tokenizer
somali-tokenizer encode "Soomaaliya waa dal."            # 5446 406 785 29
somali-tokenizer encode --format tokens "Soomaaliya waa dal."
somali-tokenizer decode 5446 406 785 29
echo "Nabad iyo caano" | somali-tokenizer encode --format json
somali-tokenizer inspect
```

`--tokenizer PATH` uses another artifact; with the `http` feature, `--hub REPO` loads one
from the Hub.

### Training, benchmarking, corpus statistics

```bash
# Train on a Somali NLP Corpus release. The 0.8% evaluation split is held out by id hash,
# documents are cleaned and fed line by line; a run record is written beside the artifact.
somali-tokenizer train --corpus data/final/final_so.jsonl \
    --output artifacts/scratch/somali-bpe-v2.json

# Vocabulary sweep: train the largest size once, derive the rest by truncating merges.
somali-tokenizer train --corpus data/final/final_so.jsonl --sweep 65536
somali-tokenizer train --derive-from artifacts/scratch/sweep/somali-bpe-v2-65536.json \
    --sweep 16384,32000,48000

# Score tokenizers on the evaluation split (pass the release corpus or eval_holdout.jsonl).
somali-tokenizer benchmark --eval data/final/final_so.jsonl \
    --tokenizer v1=artifacts/releases/v1/tokenizer.json \
    --tokenizer v2=artifacts/releases/v2/tokenizer.json

# Tokenize the whole corpus and report measured token counts per source.
somali-tokenizer stats --corpus data/final/final_so.jsonl
```

Nothing writes into `artifacts/releases/`; promoting an artifact is a deliberate manual
step. Reports go to `reports/` by default.

## Guarantees

- `decode(encode(x)) == NFC(x)` for any input: the round-trip is lossless.
- No unknown token can be produced: all 256 bytes are in the vocabulary.
- Token ids equal those of the Python `tokenizers` library on the same artifact; the parity
  fixture in `tests/fixtures/parity_v2.jsonl` enforces it.
- Training, the holdout split, the benchmark, and corpus statistics reproduce the Python
  reference in `python-reference/`; fixtures generated by `make_parity_fixture.py` enforce
  it (training: identical vocabulary and merges).

## Minimum Rust version

1.85 with default features. The `http` feature needs 1.88.
